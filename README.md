# Cloudtelega

Telegram как облачное хранилище для фото и видео с телефона — iPhone или Android —
либо с внешнего USB-диска.

Программа сканирует диск (или смонтированный телефон), находит все фото и видео,
считает sha256 каждого файла, отправляет их **по порядку** (хронологически) в
приватный канал/группу и записывает отправленное в SQLite — поэтому повторный
запуск не отправит один и тот же файл дважды, даже если он лежит в двух папках
под разными именами.

* Дата берётся **из EXIF** (для видео — из атома `mvhd`), а не из даты файла: порядок
  отправки и подпись соответствуют моменту съёмки, а не копирования на диск.
* Можно раскладывать архив **по топикам-годам** (`TOPIC_MODE=year`).
* Файлы **до 50 МБ** уходят через бота (Bot API), **больше 50 МБ** — от имени вашего
  аккаунта (MTProto), лимит 2 ГБ (4 ГБ с Premium).
* HEIC/HEIF с iPhone обрабатываются отдельно: JPEG для ленты, оригинал для архива или оба.
* `IMG_0001.HEIC` и `IMG_0001.JPG` рядом — это один кадр, он уйдёт один раз.
* **Живые снимки остаются живыми** — и Live Photo с iPhone, и Motion Photo с
  Android уходят одним сообщением через `sendLivePhoto` (Bot API 10.0).

## Канал или группа? Для топиков по годам — **приватная супергруппа**

| | Приватный канал | Приватная супергруппа |
|---|---|---|
| Кто пишет | только админы (бот + вы) | все участники (но можно ограничить правами) |
| Порядок сообщений | строго хронологический | перемешивается перепиской |
| Поиск по подписи | есть | есть |
| Структура «папок» | нет (только даты/хештеги) | есть — **топики** (форум-режим) |
| Лимит участников | без ограничений | до 200 000 |
| Пересылка/скачивание | можно запретить | можно запретить |
| Лимит на файл | 2 ГБ (4 ГБ Premium) | тот же |
| Хранение | бессрочно, без квоты | бессрочно, без квоты |

**Если нужны топики по годам — берите приватную супергруппу с включёнными темами**
(Настройки группы → Темы). Тогда `TOPIC_MODE=year`, и программа сама создаст темы
«2019», «2020», «2021»… и разложит по ним снимки по дате съёмки. Каждая тема
открывается как отдельная лента — это самый удобный вид архива.

**Если топики не нужны — берите приватный канал:** единственный писатель — ваш бот,
лента чистая и строго хронологическая.

Топики в канале невозможны — это функция супергрупп. Поэтому выбор такой:
годовые папки → супергруппа-форум, максимально чистая лента → канал.

### Насколько это безопасно

Честно: приватный чат Telegram — это **не end-to-end шифрование**. E2E есть только
в «секретных чатах» один на один, и для хранилища они не годятся. Всё остальное
(каналы, группы, «Избранное») шифруется между вами и сервером, а на серверах
Telegram лежит в виде, который сам Telegram технически может прочитать. Это
означает:

* от посторонних — защищено: без ссылки-приглашения и без доступа к вашему аккаунту
  в приватный канал не попасть;
* от самого Telegram и от запросов к нему — нет. Ваши фото у стороннего провайдера
  на его условиях;
* главный практический риск — угон аккаунта. Обязательно включите
  **двухфакторную авторизацию (облачный пароль)**, проверьте список активных сессий
  и никому не пересылайте код входа;
* строка `TELEGRAM_SESSION` в `.env` — это полный доступ к аккаунту без пароля и SMS.
  Файл `.env` в `.gitignore`, права 600; на общем компьютере ей не место.

Вывод: для семейного фотоархива приватный канал/группа — разумно. Для паспортов,
документов и всего, что нельзя показывать вообще никому, — шифруйте файлы до
загрузки (например `age`/`gpg`) и держите Telegram только как транспорт; ценой
будет потеря превью и ленты.

Оговорки:
* Telegram не даёт гарантий как бэкап-провайдер. Держите **вторую копию** — это
  дополнение к диску, а не замена ему.
* В приватном канале включите «Ограничить пересылку и сохранение» — контент не
  утечёт, даже если ссылка-приглашение куда-то попадёт.
* Отправляйте **документами** (`SEND_AS_DOCUMENT=true`, по умолчанию) — иначе
  Telegram пережмёт фото и потеряет оригинал и EXIF.

### Как получить `TELEGRAM_CHAT_ID`

1. Создайте приватный канал → добавьте бота в администраторы (право «Публикация сообщений»).
2. Отправьте в канал любое сообщение и откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — там будет `"chat":{"id":-1001234567890}`.
   Либо перешлите сообщение из канала боту `@userinfobot`.
3. Ваш аккаунт (тот, которым делаете `login`) тоже должен состоять в этом канале —
   иначе крупные файлы отправить не получится.

## Установка

```bash
git clone <репозиторий> && cd Cloudtelega
npm install
cp .env.example .env   # и заполнить
```

Нужен **Node.js 22.5+** (лучше 24). Нативных модулей нет — ничего не компилируется,
`npm install` не требует `build-essential`, `python3` или `make`. База лежит на
встроенном в Node модуле `node:sqlite`.

Если Node старее 22.5, обновите его (`nvm install 24 && nvm use 24`) — или поставьте
`npm i better-sqlite3` (потребуется компилятор), программа подхватит его сама.

## Настройка в браузере — самый простой путь

```bash
npm run setup
```

Откроется страница мастера настройки (ссылку программа печатает в терминале).
Она проведёт по шагам: создать бота у @BotFather, сделать приватный канал и
добавить туда бота, войти в аккаунт для файлов больше 50 МБ, выбрать папки и
режимы отправки. Каждый шаг проверяется сразу — вслепую вводить ничего не нужно.

Что умеет мастер:

* **создаёт группу с темами за вас** — одна кнопка: заводит приватную супергруппу,
  включает темы (папки по годам) и делает бота администратором с нужными правами.
  Бот такого не может, это делает ваш аккаунт — поэтому вход в аккаунт идёт раньше;
* **находит уже готовую группу** — добавьте бота администратором, напишите там что
  угодно и нажмите «Найти мою группу»;
* **проверяет права бота** и объясняет, чего не хватает, если публиковать нельзя;
* **вход в Telegram прямо на странице** — телефон, код, облачный пароль;
* **показывает подключённые диски и iPhone**, папку можно выбрать в проводнике;
* **показывает подпись до отправки** — настоящий текст сообщения в виде пузыря
  Telegram, переключается между фото, Live Photo и видео;
* **сам определяет ваш id** для команд бота — из аккаунта или из вашего сообщения боту;
* **показывает базу отправленного** — пустая она или нет, что в ней лежит, где файл;
  список грузится порциями по 100 записей, так что архив на сотни тысяч файлов
  открывается мгновенно;
* **держит профили** — несколько независимых архивов на одном компьютере;
* **запускает отправку** и показывает прогресс, не закрывая браузер.

Всё введённое сохраняется в `.env` рядом с программой — с комментариями, так что
дальше настройки можно править и руками. Страница слушает только `127.0.0.1` и
открывается по одноразовой ссылке с токеном: из сети к ней не подключиться.

## Настройка вручную

Минимум в `.env`:

```ini
TELEGRAM_CHAT_ID=-1001234567890
TELEGRAM_BOT_TOKEN=123456:ABC...        # от @BotFather
TELEGRAM_API_ID=1234567                 # my.telegram.org -> API development tools
TELEGRAM_API_HASH=abcdef...
SCAN_PATHS=/Volumes/USB/DCIM

# нужны папки по годам? включите темы в супергруппе и поставьте:
TOPIC_MODE=year
```

Затем один раз войти в аккаунт (нужно для файлов > 50 МБ):

```bash
npm run start -- login      # телефон -> код из Telegram -> пароль 2FA
```

Строка сессии сохранится в `.env` как `TELEGRAM_SESSION`.
**Это полный доступ к вашему аккаунту — не коммитьте `.env` и никому его не показывайте.**

## Несколько человек на одном компьютере

У каждого свой **профиль**: свой бот, своя группа, свой аккаунт Telegram, свои папки
и своя база. Архивы не перемешиваются, настройки одного не видны другому.

```bash
npm run start -- profiles                    # список профилей
npm run start -- send --profile=маша         # работать в профиле «маша»
CLOUDTELEGA_PROFILE=маша npm run bot         # бот для этого профиля
```

В мастере настройки профили — списком в левой колонке, как учётные записи в
системных настройках: щелчок переключает, «+» заводит новый и сразу открывает его
настройку с первого шага, «×» на наведении удаляет чужой профиль.

Как это устроено:

* профиль по умолчанию — это `.env` и `data/cloudtelega.db` в корне, поэтому уже
  настроенная установка продолжает работать как была;
* остальные профили лежат в `profiles/<имя>/`: там `config.env` и `archive.db`;
* настройки профилей не наследуются друг от друга — токен из одного профиля
  никогда не подставится в другой;
* настоящие переменные окружения по-прежнему сильнее файла, так что
  `DB_PATH=… npm run send` работает как раньше.

Каждый профиль — отдельный процесс: чтобы боты двух человек отвечали
одновременно, запустите `npm run bot` дважды с разными `CLOUDTELEGA_PROFILE`.
Мастер настройки один на программу и переключает профиль целиком, поэтому
настраивайтесь по очереди.

Папка `profiles/` в `.gitignore`: там лежат токены и ключи от аккаунтов.

## Управление из Telegram

`npm run bot` поднимает режим команд: бот слушает вас в личке и делает то же, что CLI,
только с телефона.

```
/status          идёт ли отправка, что уже в архиве
/scan [путь]     что нового на диске (ничего не отправляет)
/send [путь]     отправить всё новое; прогресс редактируется прямо в сообщении
/stop            остановить после текущего файла
/devices         какие диски и iPhone видны прямо сейчас
/find <текст>    найти в архиве по имени или пути + ссылка на сообщение
/get <текст>     прислать файл сюда — мгновенно, по file_id, без повторной загрузки
/random [год]    случайный кадр из архива («а что было в 2019?»)
/last [n]        последние отправленные
/stats           сколько всего и по годам
/topics          топики-годы и их id
/retry           вернуть упавшие файлы в очередь
/cleanup         убрать лишние видео Live Photo (/cleanup yes — удалить)
/id              узнать свой id
```

Настройка доступа: напишите боту `/id`, добавьте полученное число в
`TELEGRAM_ADMIN_IDS` (через запятую, если вас несколько) и перезапустите.
Без этого списка бот отвечает только на `/id` — команды от посторонних отклоняются
и пишутся в лог.

Каталоги для `/scan` и `/send` ограничены значениями `SCAN_PATHS` и смонтированными
дисками — чтобы команда из чата не могла прочитать произвольную папку на компьютере.
Снимается флагом `BOT_ALLOW_ANY_PATH=true`.

Отправка идёт в фоне: бот продолжает отвечать на команды и обновляет прогресс в
том же сообщении раз в несколько секунд. Второй `/send` во время работы получит
отказ, а не запустит второй обход диска.

Держать бота живым удобно через systemd:

```ini
# /etc/systemd/system/cloudtelega.service
[Service]
WorkingDirectory=/home/user/Cloudtelega
ExecStart=/usr/bin/node src/index.js bot
Restart=always
User=user
```

## Использование

```bash
npm run setup                         # настройка в браузере
npm run devices                       # какие диски/iPhone видны + подсказки по монтированию
npm run start -- check                # проверить бота, аккаунт, чат и каталоги
npm run start -- scan --path=/Volumes/USB
npm run start -- send --path=/Volumes/USB --dry-run   # план без отправки
npm run start -- send --path=/Volumes/USB             # отправка
npm run start -- stats                # что уже загружено
npm run start -- retry                # повторить упавшие
```

Опции: `--path=` (можно несколько), `--since=2024-01-01`, `--limit=100`, `--dry-run`.
`Ctrl+C` останавливает аккуратно — после текущего файла; прогресс уже в базе,
следующий запуск продолжит с того же места.

## Как подключить телефон

### iPhone

iPhone не монтируется как обычная флешка — фото лежат за протоколом AFC/MTP.

**macOS**
```bash
brew install libimobiledevice ifuse
idevicepair pair
mkdir -p ~/iphone && ifuse ~/iphone
npm run start -- send --path=~/iphone/DCIM
```
Либо проще: «Захват изображений» (Image Capture) → выгрузить всё в папку → указать её.

**Linux**
```bash
sudo apt install libimobiledevice6 libimobiledevice-utils ifuse
idevicepair pair && mkdir -p ~/iphone && ifuse ~/iphone
npm run start -- send --path=~/iphone/DCIM
fusermount -u ~/iphone     # размонтировать
```

**Windows** — iPhone виден как MTP-устройство, Node не читает MTP напрямую:
скопируйте `Apple iPhone → Internal Storage → DCIM` в обычную папку и укажите её.

На телефоне обязательно: **Настройки → Фото → Оставлять оригиналы** (иначе iPhone
отдаёт по кабелю сконвертированные JPEG вместо HEIC) и при подключении — «Доверять
этому компьютеру».

## Как отправлять: лента или документы

`SEND_AS_DOCUMENT=false` (по умолчанию) — **лента**: фото приходят с превью, видео
играются прямо в чате, канал листается как галерея. Telegram при этом пережимает
фото и вырезает EXIF.

`SEND_AS_DOCUMENT=true` — **документы**: байт в байт оригинал со всеми метаданными,
но лента превращается в список файлов.

Компромисс: `SEND_AS_DOCUMENT=false` + `KEEP_HEIC_ORIGINAL=true` — для каждого HEIC
уходит и JPEG (смотреть), и оригинал (хранить).

Ограничения Telegram, которые программа обходит сама:
* фото больше 10 МБ превью не получает — такие уходят документом автоматически;
* HEIC и RAW Telegram как фото не показывает — оригиналы всегда идут документом;
* если Telegram отказался принимать файл как фото, он тут же отправляется документом.

## HEIC

`HEIC_MODE`:

* `auto` (по умолчанию) — в режиме ленты конвертирует в JPEG, в режиме документов
  отправляет оригинал.
* `convert` — только JPEG (`heic-convert`, чистый JS, без системных зависимостей).
* `document` — только оригинал `.heic`.
* `both` — и JPEG для ленты, и оригинал для архива.

Если конвертация не удалась (битый файл), оригинал всё равно будет отправлен.

## Даты съёмки

Дата ищется по порядку:

1. **EXIF** — `DateTimeOriginal` / `CreateDate` (jpeg, heic, png, tiff, dng);
2. **атомы видео** — `moov → mvhd` у `.mov` и `.mp4`;
3. **сайдкар Google Takeout** — `IMG_1234.jpg.json` с `photoTakenTime`;
4. **имя файла** — `IMG_20230715_143200`, `PXL_20230715…`, `2023-07-15 14.32.11`;
5. **файловая система** — более ранняя из mtime и даты создания.

Найденная дата задаёт порядок отправки, топик-год и первую строку подписи.
Если дата взята из файловой системы (то есть достоверной информации нет), в подписи
она помечается знаком `≈`. Команда `scan` показывает, сколько файлов какой источник
даты получили.

Подпись выглядит так:

```
📅 15.07.2023 14:32
DCIM/100APPLE/IMG_0715.HEIC
2.4 МБ · #y2023 #m07 · sha:9f2c41a0b3e7d5c8
```

## Живые снимки: Live Photo и Motion Photo

Telegram с апреля 2026 понимает и то, и другое нативно. Для ботов это метод
`sendLivePhoto` (Bot API 10.0), который принимает сразу два файла — кадр и короткое
видео. Программа готовит эту пару сама, но по-разному для разных телефонов:

* **iPhone** кладёт видео отдельным файлом: `IMG_0007.HEIC` + `IMG_0007.MOV`
  (в выгрузке iCloud — `IMG_0007_HEVC.MOV`). Пара склеивается по имени, HEIC
  конвертируется в JPEG, видео идёт как есть.
* **Android** (Pixel, Samsung и другие) прячет видео **внутрь JPEG**: файл один, а
  в его хвосте дописан MP4. Программа находит границу, разрезает файл на кадр и
  видео и отправляет тем же живым снимком. Если это не Motion Photo или разобрать
  не вышло — уходит обычным фото, ничего не теряется.

Режимы (`LIVE_PHOTO_VIDEOS`):

* `live` — парой, одним сообщением (по умолчанию);
* `send` — кадр и видео двумя отдельными сообщениями;
* `skip` — видео не отправлять, только кадр.

Что важно знать:

* Отправка идёт **через бота**. Если бот не настроен или его Bot API server старый
  (метода `sendLivePhoto` там нет), пара автоматически уходит двумя сообщениями —
  ничего не теряется, просто это уже не Live Photo. Через аккаунт (MTProto) пара
  не собирается: она всегда мелкая и всегда проходит через бота.
* В архивном режиме (`SEND_AS_DOCUMENT=true`) Live Photo не собирается: там смысл
  в несжатых оригиналах, поэтому оба файла уходят как документы.
* Видео Live Photo записывается в базу вместе с кадром — если тот же `.MOV`
  попадётся отдельно в другой папке, он не уйдёт второй раз.
* Ограничения: кадр до 10 МБ, видео до 50 МБ. Если пара не влезает, она уходит
  двумя сообщениями.

## Подпись под сообщением

`CAPTION_STYLE=pretty` (по умолчанию) — дата крупно, техническое мелким шрифтом,
путь и хеш спрятаны в раскрывающуюся цитату:

```
📷 12 марта 2020, 23:16
iPhone 11 Pro · 3.2 МБ · Live Photo
#2020 #март2020 #live #IMG_0373
▸ 2020/IMG_0373.jpg
  sha:fb1e7549ae08bcc3
```

Модель камеры берётся из EXIF, хештеги делают архив искомым: `#2020` — весь год,
`#март2020` — месяц, `#IMG_0373` — конкретный кадр. Если достоверной даты съёмки
нет, перед ней ставится `≈`.

Другие варианты: `plain` — простой текст без разметки (как было раньше),
`minimal` — только дата и хештеги.

## Дубликаты

Три независимых уровня — ни один файл не уйдёт дважды:

1. **По содержимому.** sha256 каждого файла хранится в базе. Один и тот же снимок
   под разными именами и в разных папках отправится один раз.
2. **По имени в пределах одного запуска.** `IMG_0001.HEIC` и `IMG_0001.JPG` в одном
   каталоге — это один кадр в двух форматах: отправляется один, выбор задаёт
   `PAIR_PREFER` (`auto`: JPEG для ленты, оригинал для документов). `.MOV` рядом с
   фото того же имени — это Live Photo: по умолчанию он не отбрасывается, а уходит
   вместе с кадром одним сообщением (см. раздел выше).
3. **По имени между запусками.** Если тот же кадр в другом формате уже был отправлен
   раньше, он опознаётся по имени без расширения **и** совпадающей дате съёмки
   (`CROSS_RUN_NAME_CHECK`). Одного имени мало: `IMG_0001` встречается на каждом
   iPhone, поэтому дата обязательна.

**Уже отправленные дубли.** Если архив собирался старой версией, видео Live Photo
могли уйти отдельными сообщениями. `npm run start -- cleanup` покажет такие
(команда `/cleanup` у бота — то же самое), а `cleanup --yes` удалит эти сообщения
и пометит файлы в базе, чтобы они не отправились снова. Бот должен быть админом
с правом «Удаление сообщений».

**Повторное подключение того же диска.** Ничего не отправится второй раз: решает
sha256 из базы, а не путь. Чтобы при этом не перечитывать терабайты, хеши кэшируются
не только по пути, но и по «имя + размер + время файла» (`FAST_REMOUNT_MATCH=true`) —
поэтому диск, смонтированный как `/Volumes/USB-1` вместо `/Volumes/USB`, обрабатывается
почти мгновенно.

## База отправленного

SQLite (`data/cloudtelega.db`), через встроенный `node:sqlite`; при желании можно
заставить использовать конкретный драйвер: `CLOUDTELEGA_SQLITE=node|better`.

* `files` — `sha256` (UNIQUE, ключ дедупликации), имя, путь, размер, дата съёмки и её
  источник, имя без расширения, статус (`pending` / `sent` / `failed` / `skipped`),
  способ отправки, топик, `message_id`, ошибка, а также **`file_id`**,
  `file_unique_id`, `file_type` и `video_file_id` (видео Live Photo).
* `hash_cache` — кэш sha256 по `(путь, размер, mtime)`, чтобы повторный запуск не
  перечитывал весь диск заново.
* `topics` — соответствие «год → message_thread_id» для режима топиков.
* `meta` — служебное.

Первые 16 символов хеша есть в подписи каждого сообщения — по ним файл находится
поиском внутри Telegram.

```bash
sqlite3 data/cloudtelega.db "select name, size, status, message_id, file_id from files limit 20;"
```

### Зачем нужен `file_id`

Это идентификатор уже загруженного файла на серверах Telegram. По нему бот может
отправить файл **мгновенно и без повторной загрузки** — на этом работают `/get` и
`/random`. Полезно знать:

* `file_id` действителен только для того бота, который загрузил файл; для другого
  бота он бесполезен (а вот `file_unique_id` одинаков у всех и годится как ключ
  сравнения);
* у файлов, ушедших через аккаунт (больше 50 МБ), `file_id` нет — бот их не
  загружал. Такие бот присылает через `copyMessage` из хранилища, результат тот же;
* у Live Photo хранятся оба идентификатора: кадра (`file_id`) и видео
  (`video_file_id`), поэтому `/get` пересобирает Live Photo целиком;
* `/status` показывает, у скольких файлов есть `file_id`.

## Лимиты и надёжность

* Bot API: 50 МБ на файл. Если поднять свой
  [Bot API server](https://github.com/tdlib/telegram-bot-api) с `--local` и указать
  `TELEGRAM_BOT_API_ROOT`, лимит станет 2000 МБ.
* MTProto (аккаунт): 2 ГБ, с Premium 4 ГБ.
* Фото с превью: до 10 МБ, всё что больше — автоматически документом.
* Live Photo: кадр до 10 МБ, видео до 50 МБ, отправка только через бота.
* Flood-лимиты: между отправками пауза `SEND_DELAY_MS` (по умолчанию 1200 мс),
  ответ `429 retry_after` от Bot API обрабатывается автоматически, FLOOD_WAIT в
  MTProto — тоже. При заливке большого архива не ставьте паузу в 0.
* Сеть отвалилась — файл помечается `failed`, запуск продолжается; `retry` вернёт
  его в очередь.

## Если что-то не ставится

**`npm error command failed … better-sqlite3` / `gyp ERR! not found: make`** — старая
версия проекта тянула нативный модуль. Обновитесь и переустановите зависимости:

```bash
git pull
rm -rf node_modules package-lock.json
npm install
```

Native-зависимостей в проекте больше нет, компилятор не нужен.

**`ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite`** — Node старее 22.5. Обновите Node
(`nvm install 24 && nvm use 24`) либо поставьте `npm i better-sqlite3`.

**`input buffer is not a HEIC image`** — файл с расширением `.heic`, но не HEIC внутри.
Оригинал в этом случае всё равно отправляется, терять ничего не нужно.
