# Cloudtelega

Telegram как облачное хранилище для фото и видео с телефона — iPhone или Android —
либо с внешнего USB-диска.

Программа сканирует диск (или смонтированный телефон), находит все фото и видео,
считает sha256 каждого файла, отправляет их **по порядку** (хронологически) в
приватный канал/группу и записывает отправленное в SQLite — поэтому повторный
запуск не отправит один и тот же файл дважды, даже если он лежит в двух папках
под разными именами.

* Дата берётся **из EXIF** (для видео — из атома `mvhd`), а не из даты файла: порядок
  отправки и подпись соответствуют моменту съёмки, а не копирования на диск.
* Можно раскладывать архив **по топикам-годам** (`TOPIC_MODE=year`).
* Файлы **до 50 МБ** уходят через бота (Bot API), **больше 50 МБ** — от имени вашего
  аккаунта (MTProto), лимит 2 ГБ (4 ГБ с Premium).
* HEIC/HEIF с iPhone обрабатываются отдельно: JPEG для ленты, оригинал для архива или оба.
* `IMG_0001.HEIC` и `IMG_0001.JPG` рядом — это один кадр, он уйдёт один раз.
* **Живые снимки остаются живыми** — и Live Photo с iPhone, и Motion Photo с
  Android уходят одним сообщением через `sendLivePhoto` (Bot API 10.0).

## Канал или группа? Для топиков по годам — **приватная супергруппа**

| | Приватный канал | Приватная супергруппа |
|---|---|---|
| Кто пишет | только админы (бот + вы) | все участники (но можно ограничить правами) |
| Порядок сообщений | строго хронологический | перемешивается перепиской |
| Поиск по подписи | есть | есть |
| Структура «папок» | нет (только даты/хештеги) | есть — **топики** (форум-режим) |
| Лимит участников | без ограничений | до 200 000 |
| Пересылка/скачивание | можно запретить | можно запретить |
| Лимит на файл | 2 ГБ (4 ГБ Premium) | тот же |
| Хранение | бессрочно, без квоты | бессрочно, без квоты |

**Если нужны топики по годам — берите приватную супергруппу с включёнными темами**
(Настройки группы → Темы). Тогда `TOPIC_MODE=year`, и программа сама создаст темы
«2019», «2020», «2021»… и разложит по ним снимки по дате съёмки. Каждая тема
открывается как отдельная лента — это самый удобный вид архива.

**Если топики не нужны — берите приватный канал:** единственный писатель — ваш бот,
лента чистая и строго хронологическая.

Топики в канале невозможны — это функция супергрупп. Поэтому выбор такой:
годовые папки → супергруппа-форум, максимально чистая лента → канал.

### Насколько это безопасно

Честно: приватный чат Telegram — это **не end-to-end шифрование**. E2E есть только
в «секретных чатах» один на один, и для хранилища они не годятся. Всё остальное
(каналы, группы, «Избранное») шифруется между вами и сервером, а на серверах
Telegram лежит в виде, который сам Telegram технически может прочитать. Это
означает:

* от посторонних — защищено: без ссылки-приглашения и без доступа к вашему аккаунту
  в приватный канал не попасть;
* от самого Telegram и от запросов к нему — нет. Ваши фото у стороннего провайдера
  на его условиях;
* главный практический риск — угон аккаунта. Обязательно включите
  **двухфакторную авторизацию (облачный пароль)**, проверьте список активных сессий
  и никому не пересылайте код входа;
* строка `TELEGRAM_SESSION` в `.env` — это полный доступ к аккаунту без пароля и SMS.
  Файл `.env` в `.gitignore`, права 600; на общем компьютере ей не место.

Вывод: для семейного фотоархива приватный канал/группа — разумно. Для паспортов,
документов и всего, что нельзя показывать вообще никому, — шифруйте файлы до
загрузки (например `age`/`gpg`) и держите Telegram только как транспорт; ценой
будет потеря превью и ленты.

Оговорки:
* Telegram не даёт гарантий как бэкап-провайдер. Держите **вторую копию** — это
  дополнение к диску, а не замена ему.
* В приватном канале включите «Ограничить пересылку и сохранение» — контент не
  утечёт, даже если ссылка-приглашение куда-то попадёт.
* Отправляйте **документами** (`SEND_AS_DOCUMENT=true`, по умолчанию) — иначе
  Telegram пережмёт фото и потеряет оригинал и EXIF.

### Если нужной группы нет в списке

Telegram устроен так, что бот узнаёт о группе **только вместе со свежим
сообщением в ней**. Прав администратора для этого мало: пока в группе никто
ничего не написал, для бота её как будто не существует. Поэтому готовая
группа с архивом может не показаться в списке — особенно если писали в неё
последний раз давно.

Два пути:

* **написать в группе любое сообщение** и открыть список снова — программа
  запомнит группу навсегда, в своей базе, и больше её не потеряет;
* **«Указать группу вручную»** — последний пункт в списке выбора. Откройте
  группу в Telegram, нажмите на любое сообщение → «Копировать ссылку»
  и вставьте. Подойдёт и `@имя` группы, и её числовой id. Программа спросит
  Telegram про этот чат напрямую — сообщение в группе для этого не нужно.

Пригласительная ссылка вида `t.me/+AbCdEf` не подойдёт: по ней Telegram чат
не отдаёт. Нужна ссылка на сообщение (`t.me/c/…`), `@имя` или id.

### Как получить `TELEGRAM_CHAT_ID`

1. Создайте приватный канал → добавьте бота в администраторы (право «Публикация сообщений»).
2. Отправьте в канал любое сообщение и откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — там будет `"chat":{"id":-1001234567890}`.
   Либо перешлите сообщение из канала боту `@userinfobot`.
3. Ваш аккаунт (тот, которым делаете `login`) тоже должен состоять в этом канале —
   иначе крупные файлы отправить не получится.

## Установка

```bash
git clone <репозиторий> && cd Cloudtelega
npm install
cp .env.example .env   # и заполнить
```

Нужен **Node.js 22.5+** (лучше 24). Нативных модулей нет — ничего не компилируется,
`npm install` не требует `build-essential`, `python3` или `make`. База лежит на
встроенном в Node модуле `node:sqlite`.

Если Node старее 22.5, обновите его (`nvm install 24 && nvm use 24`) — или поставьте
`npm i better-sqlite3` (потребуется компилятор), программа подхватит его сама.

## Настройка в браузере — самый простой путь

```bash
npm run setup
```

Откроется страница мастера настройки (ссылку программа печатает в терминале).
Она проведёт по шагам: создать бота у @BotFather, сделать приватный канал и
добавить туда бота, войти в аккаунт для файлов больше 50 МБ, выбрать папки и
режимы отправки. Каждый шаг проверяется сразу — вслепую вводить ничего не нужно.

Что умеет мастер:

* **создаёт группу с темами за вас** — одна кнопка: заводит приватную супергруппу,
  включает темы (папки по годам) и делает бота администратором с нужными правами.
  Бот такого не может, это делает ваш аккаунт — поэтому вход в аккаунт идёт раньше;
* **находит уже готовую группу** — добавьте бота администратором, напишите там что
  угодно и нажмите «Найти мою группу»;
* **проверяет права бота** и объясняет, чего не хватает, если публиковать нельзя;
* **вход в Telegram прямо на странице** — телефон, код, облачный пароль;
* **показывает подключённые диски и iPhone**, папку можно выбрать в проводнике;
* **показывает подпись до отправки** — настоящий текст сообщения в виде пузыря
  Telegram, переключается между фото, Live Photo и видео;
* **сам определяет, кому доверить команды боту** — показывает вас, участников
  вашей группы и тех, кто писал боту, с фотографиями и username; числовые id
  остаются внутри;
* **показывает базу отправленного** — пустая она или нет, что в ней лежит, где файл;
  список грузится порциями по 100 записей, есть поиск по имени и папке, а каждая
  запись — ссылка на само сообщение в Telegram;
* **держит профили** — несколько независимых архивов на одном компьютере, у каждого
  свой вид (тема, цвет, аватар из Telegram) и своя защита: PIN, пароль или код,
  который приходит в Telegram;
* **не спрашивает «сохранить?»** — настройки применяются сразу, как в системных
  настройках; отдельная кнопка осталась только там, где нужно что-то проверить
  или подключить;
* **прячет технику** — вместо числовых id людей и групп показываются имена,
  username и фотографии: командовать ботом разрешают, выбрав человека из списка
  участников группы, группу — из списка найденных, с её аватаром в кружке;
* **открывается витриной хранилищ** — диск и фотоархив; у каждого свой чат
  в Telegram, свои файлы и свой список тех, кого вы туда пустили;
  шаги настройки убраны в свёрнутый раздел, добавить новое приложение —
  одна запись в реестре;
* **держит диск для любых файлов** — перетаскивание прямо в окно, папки,
  поиск, плитка или список, скачивание обратно;
* **раздаёт доступ ссылками со сроком** — на день, неделю, месяц; когда срок
  выходит, гостя убирают из чата, не банят;
* **сам поднимает бота** — и бот тут же пишет вам «готов к работе»: команды
  в терминале для этого набирать не нужно;
* **показывает, как подключить телефон** — по шагам и под вашу систему: Windows,
  macOS или Linux программа определяет сама, отдельно для iPhone и для Android,
  команды копируются кнопкой;
* **запускает отправку** и показывает прогресс, не закрывая браузер.

Всё введённое сохраняется в `.env` рядом с программой — с комментариями, так что
дальше настройки можно править и руками. Страница слушает только `127.0.0.1` и
открывается по одноразовой ссылке с токеном: из сети к ней не подключиться.

## Настройка вручную

Минимум в `.env`:

```ini
TELEGRAM_CHAT_ID=-1001234567890
TELEGRAM_BOT_TOKEN=123456:ABC...        # от @BotFather
TELEGRAM_API_ID=1234567                 # my.telegram.org -> API development tools
TELEGRAM_API_HASH=abcdef...
SCAN_PATHS=/Volumes/USB/DCIM

# нужны папки по годам? включите темы в супергруппе и поставьте:
TOPIC_MODE=year
```

Затем один раз войти в аккаунт (нужно для файлов > 50 МБ):

```bash
npm run start -- login      # телефон -> код из Telegram -> пароль 2FA
```

Строка сессии сохранится в `.env` как `TELEGRAM_SESSION`.
**Это полный доступ к вашему аккаунту — не коммитьте `.env` и никому его не показывайте.**

## Несколько человек на одном компьютере

У каждого свой **профиль**: свой бот, своя группа, свой аккаунт Telegram, свои папки
и своя база. Архивы не перемешиваются, настройки одного не видны другому.

```bash
npm run start -- profiles                    # список профилей
npm run start -- send --profile=маша         # работать в профиле «маша»
CLOUDTELEGA_PROFILE=маша npm run bot         # бот для этого профиля
```

В мастере настройки профили — списком в левой колонке, как учётные записи в
системных настройках: щелчок переключает, «+» заводит новый и сразу открывает его
настройку с первого шага, «×» на наведении удаляет чужой профиль. Ниже, отдельно
от шагов настройки, — то, что открывают время от времени: «Профиль и защита»,
«База отправленного» и «Закрыть профиль».

Как это устроено:

* профиль по умолчанию — это `.env` и `data/cloudtelega.db` в корне, поэтому уже
  настроенная установка продолжает работать как была;
* остальные профили лежат в `profiles/<имя>/`: там `config.env` и `archive.db`;
* настройки профилей не наследуются друг от друга — токен из одного профиля
  никогда не подставится в другой;
* настоящие переменные окружения по-прежнему сильнее файла, так что
  `DB_PATH=… npm run send` работает как раньше.

Каждый профиль — отдельный процесс: мастер держит бота того профиля, который
открыт сейчас, и переключает его вместе с профилем. Чтобы боты двух человек
отвечали одновременно, запустите `npm run bot` дважды с разными
`CLOUDTELEGA_PROFILE`.
Мастер настройки один на программу и переключает профиль целиком, поэтому
настраивайтесь по очереди.

Папка `profiles/` в `.gitignore`: там лежат токены и ключи от аккаунтов.

### Почему в базе нет картинок

В базе отправленного каждая запись показана значком по типу файла, датой
и именем — списком или плиткой. Самих снимков программа не тянет намеренно.

Раньше тянула: у каждого сообщения Telegram держит маленькую превьюшку,
и программа подтягивала её по сохранённому идентификатору. Беда в том, что
страница базы грузится сотнями записей сразу, а каждая превьюшка — это два
обращения к Bot API (`getFile` и загрузка файла). Двести запросов подряд —
и Telegram сажает бота на flood limit: вместе с превью встаёт и отправка
архива. Ради картинок, которые всё равно видно в самом Telegram, это плохой
размен, поэтому загрузка убрана.

Сам снимок в полном размере открывается в один щелчок: каждая строка и каждая
плитка — ссылка на сообщение в Telegram.

Идентификатор превью (`thumb_file_id`) по-прежнему сохраняется — несколько байт
в строке базы, зато превью можно будет показывать снова, если найдётся способ
делать это без потока запросов.

Аватары групп и людей в списках выбора остались: их единицы за открытие списка,
и они точно так же нигде не сохраняются — идут из Telegram прямо в браузер,
мимо диска.

### Профиль: вид и защита

Панель «Профиль и защита» в мастере:

* **аватар и username из Telegram** — кнопка «Обновить из Telegram» тянет фото
  профиля, username и признак Premium (с Premium лимит на файл становится 4 ГБ
  вместо 2, программа это учитывает сама). Пока аккаунт не подключён, на той же
  кнопке написано «Войти в свой Telegram» и ведёт она сразу на шаг 3;
* **имя одно** — «Имя профиля» — и оно только про эту программу. Имя, фамилию
  и фото в самом Telegram программа не трогает: это настоящий аккаунт, и менять
  их правильнее в приложении Telegram, а здесь они только показываются;
* **своя картинка** вместо аватара — если аватар из Telegram не нравится;
* **тема, цвет и фон** — светлая, тёмная или как в системе, акцентный цвет и
  обои рабочей области: готовый набор, свой цвет или градиент (два цвета
  и направление перехода, образец меняется на глазах) либо своя картинка,
  как в чатах Telegram. Обои ложатся только на рабочую область: боковое меню
  остаётся как было. У каждого профиля свои, так что перепутать чужой архив
  трудно даже взглядом;
* **защита профиля** — чтобы домашние случайно не отправили фото не в свой архив:

| Способ | Как входить | Если забыли |
|---|---|---|
| PIN | 4–8 цифр | код в Telegram |
| Пароль | от 6 символов | код в Telegram |
| Код в Telegram | шестизначный код боту в личку | запросить новый код |

Секрет хранится не в открытом виде, а солёным scrypt-хешем в
`profile.json` рядом с базой. Код в Telegram живёт 5 минут, срабатывает один раз
и приходит через бота этого профиля его владельцу (нужны токен бота и ваш id
в списке владельцев). Профиль сам закрывается после указанного времени
бездействия, «Закрыть профиль» в левой колонке делает это немедленно, а время
последнего входа видно и в списке профилей, и на панели профиля.

И PIN, и пароль придумываются в отдельном окне, с повтором: PIN — по одной цифре,
как на телефоне (четыре или шесть ячеек, ввод сам переходит к следующей, понимает
Backspace и вставку кода целиком), пароль — строкой, «Готово» загорается, когда
символов хватает.

Пока профиль закрыт, страница показывает экран входа, а сервер отвечает на всё
остальное кодом 423 — то есть замок настоящий, а не нарисованный. На том же
экране — остальные профили и «Добавить профиль»: закрыли свой, чтобы уступить
компьютер, — второй человек заходит в свой, не открывая ваш.

В «опасной зоне» профиля — **отключить аккаунт Telegram** (программа забудет ключ,
архив и сам аккаунт останутся) и **удалить профиль**: как удаление репозитория на
GitHub, с перечислением последствий и вводом имени профиля для подтверждения.

Важно понимать границы: это защита от домашних, а не от того, кто имеет доступ
к файлам компьютера. Токены и ключ от аккаунта лежат в файлах профиля, и PIN их
не шифрует. Бот в Telegram тоже слушается своего списка владельцев независимо
от замка в программе.

## Управление из Telegram

Включается на вкладке **«Бот»** в блоке «Этот профиль» — там же список того,
что боту можно написать.

Бот включается сам вместе с мастером настройки — ничего запускать не нужно.
Как только есть токен и указано, кто может им командовать, он пишет владельцу
в личку «готов к работе» и дальше слушает команды: то же, что умеет CLI, только
с телефона. Выключить и включить обратно можно на шаге «Проверка и запуск»,
там же видно, на связи он или нет.

Бот живёт, пока открыта программа. Если мастер не нужен, а бот нужен —
`npm run bot` поднимает только его. Двух сразу запускать нельзя: Telegram
отдаёт команды одному получателю, поэтому либо мастер, либо отдельный процесс.

```
/status          идёт ли отправка, что уже в архиве
/scan [путь]     что нового на диске (ничего не отправляет)
/send [путь]     отправить всё новое; прогресс редактируется прямо в сообщении
/stop            остановить после текущего файла
/devices         какие диски и iPhone видны прямо сейчас
/find <текст>    найти в архиве по имени или пути + ссылка на сообщение
/get <текст>     прислать файл сюда — мгновенно, по file_id, без повторной загрузки
/random [год]    случайный кадр из архива («а что было в 2019?»)
/last [n]        последние отправленные
/stats           сколько всего и по годам
/topics          топики-годы и их id
/retry           вернуть упавшие файлы в очередь
/cleanup         убрать лишние видео Live Photo (/cleanup yes — удалить)
/id              узнать свой id

/drive           сколько файлов на диске и где он лежит
/share [срок]    ссылка-приглашение: день | неделя | месяц | год | навсегда
/guests          кто внутри и сколько ему осталось
/kick <id>       закрыть доступ (без бана — сможет войти снова)
```

Настройка доступа: в мастере, на шаге «Как отправлять», выберите людей из списка —
там участники вашей группы и все, кто писал боту. Вручную то же самое:
`TELEGRAM_ADMIN_IDS` через запятую. Без этого списка бот отвечает только на `/id` —
команды от посторонних отклоняются и пишутся в лог.

Каталоги для `/scan` и `/send` ограничены значениями `SCAN_PATHS` и смонтированными
дисками — чтобы команда из чата не могла прочитать произвольную папку на компьютере.
Снимается флагом `BOT_ALLOW_ANY_PATH=true`.

Отправка идёт в фоне: бот продолжает отвечать на команды и обновляет прогресс в
том же сообщении раз в несколько секунд. Второй `/send` во время работы получит
отказ, а не запустит второй обход диска.

Держать бота живым удобно через systemd:

```ini
# /etc/systemd/system/cloudtelega.service
[Service]
WorkingDirectory=/home/user/Cloudtelega
ExecStart=/usr/bin/node src/index.js bot
Restart=always
User=user
```

## Использование

```bash
npm run setup                         # настройка в браузере
npm run devices                       # какие диски/iPhone видны + подсказки по монтированию
npm run start -- check                # проверить бота, аккаунт, чат и каталоги
npm run start -- scan --path=/Volumes/USB
npm run start -- send --path=/Volumes/USB --dry-run   # план без отправки
npm run start -- send --path=/Volumes/USB             # отправка
npm run start -- stats                # что уже загружено
npm run start -- retry                # повторить упавшие
```

Опции: `--path=` (можно несколько), `--since=2024-01-01`, `--limit=100`, `--dry-run`.
`Ctrl+C` останавливает аккуратно — после текущего файла; прогресс уже в базе,
следующий запуск продолжит с того же места.

## Как устроен интерфейс

Программа открывается **главным экраном** — витриной приложений, а не первым
шагом мастера. Каждое приложение это плитка с живыми числами: сколько файлов
на диске, сколько снимков в архиве, сколько гостей внутри. Слева те же
приложения списком.

Шаги настройки убраны в свёрнутый раздел «Настройка»: они нужны один раз.
Пока бот или чат не подключены, на главной висит полоска «Осталось
подключить…» с кнопкой, ведущей ровно на нужный шаг, а программа при запуске
сама открывается на настройке, а не на витрине.

**Добавить новое приложение — одна запись в реестре.** В `src/web/public/app.js`
есть массив `APPS`: id, название, описание, цвет, иконка, `ready()` и `stat()`.
Из него строятся и плитки на главной, и пункты бокового меню — больше нигде
ничего править не нужно.

```js
{
  id: 'notes',                       // совпадает с id панели: <section id="pane-notes">
  title: 'Заметки',
  about: 'Что-нибудь новое',
  tint: '#ff2d55',
  icon: '<path d="..."/>',           // внутренности <svg viewBox="0 0 22 22">
  ready: () => Boolean(state?.settings.chatId),
  stat: () => '12 заметок',
}
```

## Диск: любые файлы, а не только снимки

Архив снимков и диск — две разные вещи в одной программе. Снимки идут лентой
с датами и живыми фото; на диск кладутся любые файлы — документы, архивы,
музыка, проекты — **всегда оригиналом, без пережатия**.

### Канал или группа для диска?

**Годится и то, и другое** — выбирайте по тому, как вы работаете.

**Канал** удобнее, когда над диском работают несколько человек: подписи
к файлам там правятся в любой момент, а писать в ленту могут только
администраторы, так что посторонний ничего не засорит. Тем в канале нет,
поэтому папки живут только в программе — в самом Telegram это одна общая лента.

**Супергруппа с темами** удобнее, когда важно видеть папки и в Telegram:

* **темы = папки.** Папка на компьютере становится темой в чате:
  «Отчёты», «Музыка», «Проекты» — и её видно прямо в Telegram;
* **ссылки-приглашения и удаление участников** работают одинаково и в канале,
  и в группе, так что здесь разницы нет.

Если боитесь, что гости начнут писать в чат, — в настройках группы уберите
у обычных участников право отправлять сообщения. Получится тот же канал,
только с папками.

**Диску нужен свой чат, отдельный от снимков.** Не из-за техники:
к диску вы будете давать доступ посторонним, а в общем чате им были бы видны
и ваши личные снимки. Поэтому чат, занятый соседним хранилищем, в выборе
не предлагается — **кроме того, который это хранилище использует прямо
сейчас**: свой чат из своего же выбора пропасть не может, даже если диск
и снимки указывают на один и тот же. Такой чат помечен «выбран сейчас»,
а шапка обоих хранилищ предупреждает: кого пустите на диск, тот увидит
и снимки.

Где лежит диск, написано прямо под заголовком «Диск» — названием чата и его
аватаркой, а не числовым id. Щелчок по нему открывает выбор: первым пунктом
«Создать новую группу» (программа заведёт приватную супергруппу с темами
и сама сделает бота администратором), дальше — чаты, которые бот уже видит,
с пометками «группа/канал», «с темами» и «здесь ваши снимки».

### Что умеет диск

Панель «Диск» — обычный файловый менеджер, только вместо жёсткого диска Telegram.

* **перетаскивание.** Бросьте файлы прямо в окно — они уедут в Telegram.
  Байты идут потоком, поэтому гигабайтный архив не держится в памяти.
  Кнопка «Загрузить» — то же самое через обычный выбор файлов;
* **видно, что происходит.** Под списком появляется панель загрузки:
  «Загружаю 5 файлов», сколько уже ушло и сколько всего весит, а у каждого
  файла своя полоска. Пока браузер отдаёт байты, на полоске проценты; когда
  файл ушёл к нам и мы передаём его в Telegram, по полоске бежит блик
  и написано «отправляю…»; в конце — зелёная галочка или красный крестик
  с причиной. Удачную пачку панель прячет сама, с ошибками — оставляет;
* **папки, в том числе вложенные.** «Новая папка» заводит тему в чате: папка
  на диске видна и в самом Telegram. Папка создаётся там, где вы сейчас стоите,
  поэтому «Договоры → 2026 → Аренда» делается тремя нажатиями. Внутрь заходят
  щелчком, наверх — по «хлебным крошкам»; папка с компьютера уезжает целиком,
  со всем деревом внутри. Файл можно переложить в другую папку, а саму папку —
  удалить вместе со всем содержимым: тема в Telegram при этом тоже уходит.
  Удаление необратимо, корзины у тем нет, поэтому программа спрашивает
  подтверждение и пишет, сколько именно файлов исчезнет;
* **заметки к файлам.** Подпись под файлом правится прямо из программы
  и меняется в самом сообщении Telegram — её видят все, у кого есть доступ
  к чату. Ради этого диск и удобнее держать в канале: там подпись правится
  в любой момент;
* **файлы, выложенные прямо в Telegram, подхватываются сами.** Бросили документ
  в чат диска с телефона — программа увидит его при следующей проверке и внесёт
  в список. Сам файл никуда не скачивается: он уже в облаке. Отпечатком служит
  `file_unique_id`, а не `sha256` — посчитать настоящий хеш можно только скачав
  файл целиком. Отсюда честное ограничение: один и тот же файл, залитый
  и с компьютера, и с телефона, останется двумя записями;
* **поиск** по всему диску, не только по текущей папке: поле с лупой
  в панели над файлами, крестик очищает, Escape — тоже;
* **плиткой или списком** — как в проводнике;
* **скачать обратно** на компьютер: файл возвращается в свою папку.
  Скачивание идёт через аккаунт, потому что бот отдаёт только файлы до 20 МБ;
* **не грузит одно и то же дважды** — тот же sha256, что и у снимков;
* **убрать с диска** — удаляет сообщение и запись.

Отдельной строкой в блоке «Ещё» внизу — **загрузка папки с компьютера
целиком**. Кнопка открывает обычный выбор папки, а не просит вписать путь
руками: браузер отдаёт файлы вместе с их путём внутри выбранной папки,
поэтому дерево на диске повторяет дерево на компьютере — «Документы →
Договоры → 2026 → Аренда» так и лягут друг в друга. Ход виден в том же
окошке загрузки в правом нижнем углу; никуда переключаться не надо.

Из Telegram: `/drive` — сколько лежит и где.

## Совместная работа: общий список

Список файлов лежит в SQLite на компьютере, и у каждого участника он свой.
Чтобы все видели одно и то же, вкладка **«Общий список»** выкладывает его
в тот же чат, где лежат сами файлы, отдельным сообщением. Кто открыл чат —
тот и забрал свежий список кнопкой «Забрать».

Правило слияния одно: **чужие записи только добавляются, свои не затираются.**
Так у слияния нет проигравших — две базы, где каждый заливал своё, сходятся
в одну. Расплата за простоту честная: правку одной и той же записи с двух
сторон оно не разрешает, выигрывает та, что прочитана последней.

В чат уходят только имена файлов, размеры и номера сообщений — то, что и так
видно в чате. **Пути на вашем компьютере в список не попадают:** их незачем
знать тем, кого вы пустили на диск.

У диска и фотоархива списки раздельные, каждый в своём чате. Если список хоть
раз выложили вручную, программа обновляет его сама после каждой отправки —
пока не выложили, она не решает за вас, что содержимое архива можно показывать
всем в чате.

Забрать список можно только при входе в аккаунт: бот отдаёт файлы лишь
до 20 МБ, а список большого архива в них не влезает.

## Доступ: ссылки со сроком

Доступ раздаётся **отдельно для каждого хранилища** — это вкладка «Кто имеет
доступ» внутри диска и внутри фотоархива. Кого вы пустили на диск, снимков
не увидит: это разные чаты в Telegram и разные списки гостей.

Вкладка выдаёт ссылку-приглашение, у которой два разных срока — их легко
перепутать:

| Срок | Кто следит | Что происходит |
|---|---|---|
| **жизнь ссылки** | Telegram | по ссылке перестаёт пускать |
| **срок доступа** | программа | вошедшего убирают из чата |

Второго Telegram не умеет вовсе: он может закрыть ссылку, но не выгнать того,
кто уже вошёл. Это делает программа — раз в пять минут смотрит, у кого вышло
время. Отсюда следствие: **для автоматического закрытия доступа программа
должна быть запущена**. Если она стояла выключенной, всё просроченное
закроется при следующем запуске (и кнопкой «Проверить сроки сейчас»).

**Убирает, а не банит.** В Bot API нет команды «выгнать»: `banChatMember`
выкидывает из чата, но оставляет в чёрном списке навсегда. Поэтому программа
сразу за баном делает `unbanChatMember` — человек уходит из чата и при этом
может войти снова по новой ссылке.

Сроки готовые: день, неделя, месяц, год, навсегда. Плюс сколько человек пустить
(одноразовая ссылка — самый частый случай) и сколько живёт сама ссылка.
Гостя видно в списке со временем до конца доступа, его можно продлить
или закрыть доступ вручную — тоже без бана.

Из Telegram: `/share месяц` — ссылка, `/guests` — кто внутри и сколько
осталось, `/kick <id>` — закрыть доступ.

Чтобы программа видела, кто вошёл по какой ссылке, бот должен быть
администратором чата: апдейты `chat_member` Telegram шлёт только админам.

## Как подключить телефон

В мастере, на шаге «Что отправлять», эти же инструкции показаны по шагам: систему
программа определяет сама и открывает нужную, переключатель iPhone / Android рядом,
команды копируются кнопкой. Другую систему можно выбрать руками — если настраиваете
не для себя. Ниже то же самое текстом.

### iPhone

Как обычная флешка iPhone не подключается: фото лежат за протоколом AFC.

**macOS.** Простой путь — «Захват изображений» (Image Capture), он уже есть
в системе: подключить кабелем, разрешить «Доверять этому компьютеру», выбрать
папку и «Импортировать все», потом указать эту папку в программе. Кто хочет без
копирования:
```bash
brew install libimobiledevice ifuse
idevicepair pair
mkdir -p ~/iphone && ifuse ~/iphone     # отключить: umount ~/iphone
npm run start -- send --path=~/iphone/DCIM
```

**Linux.** Телефон становится обычной папкой:
```bash
sudo apt install libimobiledevice6 libimobiledevice-utils ifuse
idevicepair pair && mkdir -p ~/iphone && ifuse ~/iphone
npm run start -- send --path=~/iphone/DCIM
fusermount -u ~/iphone     # размонтировать
```

**Windows.** iPhone виден как MTP-устройство, Node не читает MTP напрямую:
Проводник → «Этот компьютер» → Apple iPhone → Internal Storage → DCIM, скопировать
на диск и указать эту папку. Если телефона не видно — поставьте iTunes или Apple
Devices, вместе с ними ставятся драйверы. Когда фото в iCloud, а не на телефоне,
проще включить в iCloud для Windows «Загружать новые фото на этот компьютер»
и указать папку iCloud Photos.

На телефоне обязательно: **Настройки → Фото → Оставлять оригиналы** (иначе iPhone
отдаёт по кабелю сконвертированные JPEG вместо HEIC) и при подключении — «Доверять
этому компьютеру».

### Android

Первым делом на телефоне: опустить шторку, нажать на уведомление о зарядке
и выбрать **«Передача файлов» (MTP)**, а не «Только зарядка». Без этого компьютер
телефон не увидит.

**Linux.** Обычно телефон появляется в файловом менеджере сам — тогда «Показать
диски и телефоны» найдёт путь вида `/run/user/1000/gvfs/mtp:host=…` без вашей
помощи. Если нет:
```bash
sudo apt install android-tools-adb        # включите «Отладку по USB» на телефоне
adb pull /sdcard/DCIM ~/android-photos
```

**Windows.** Проводник → «Этот компьютер» → ваш телефон → Internal Storage → DCIM,
скопировать на диск. Рядом с DCIM лежат Pictures, Movies и Download — фото
из WhatsApp и Telegram обычно там, их стоит забрать тоже.

**macOS.** Finder телефон не покажет: нужен Android File Transfer
(android.com/filetransfer) или OpenMTP — скопировать DCIM в папку. Через терминал:
```bash
brew install android-platform-tools       # включите «Отладку по USB» на телефоне
adb pull /sdcard/DCIM ~/android-photos
```

Живые снимки Android (Motion Photo) программа разбирает сама: видео спрятано
внутри JPEG, и оба куска уходят одним живым снимком.

## Как отправлять: лента или документы

`SEND_AS_DOCUMENT=false` (по умолчанию) — **лента**: фото приходят с превью, видео
играются прямо в чате, канал листается как галерея. Telegram при этом пережимает
фото и вырезает EXIF.

`SEND_AS_DOCUMENT=true` — **документы**: байт в байт оригинал со всеми метаданными,
но лента превращается в список файлов.

Компромисс: `SEND_AS_DOCUMENT=false` + `KEEP_HEIC_ORIGINAL=true` — для каждого HEIC
уходит и JPEG (смотреть), и оригинал (хранить).

Ограничения Telegram, которые программа обходит сама:
* фото больше 10 МБ превью не получает — такие уходят документом автоматически;
* HEIC и RAW Telegram как фото не показывает — оригиналы всегда идут документом;
* если Telegram отказался принимать файл как фото, он тут же отправляется документом.

## HEIC

`HEIC_MODE`:

* `auto` (по умолчанию) — в режиме ленты конвертирует в JPEG, в режиме документов
  отправляет оригинал.
* `convert` — только JPEG (`heic-convert`, чистый JS, без системных зависимостей).
* `document` — только оригинал `.heic`.
* `both` — и JPEG для ленты, и оригинал для архива.

Если конвертация не удалась (битый файл), оригинал всё равно будет отправлен.

## Даты съёмки

Дата ищется по порядку:

1. **EXIF** — `DateTimeOriginal` / `CreateDate` (jpeg, heic, png, tiff, dng);
2. **атомы видео** — `moov → mvhd` у `.mov` и `.mp4`;
3. **сайдкар Google Takeout** — `IMG_1234.jpg.json` с `photoTakenTime`;
4. **имя файла** — `IMG_20230715_143200`, `PXL_20230715…`, `2023-07-15 14.32.11`;
5. **файловая система** — более ранняя из mtime и даты создания.

Найденная дата задаёт порядок отправки, топик-год и первую строку подписи.
Если дата взята из файловой системы (то есть достоверной информации нет), в подписи
она помечается знаком `≈`. Команда `scan` показывает, сколько файлов какой источник
даты получили.

Подпись выглядит так:

```
📅 15.07.2023 14:32
DCIM/100APPLE/IMG_0715.HEIC
2.4 МБ · #y2023 #m07 · sha:9f2c41a0b3e7d5c8
```

## Живые снимки: Live Photo и Motion Photo

Telegram с апреля 2026 понимает и то, и другое нативно. Для ботов это метод
`sendLivePhoto` (Bot API 10.0), который принимает сразу два файла — кадр и короткое
видео. Программа готовит эту пару сама, но по-разному для разных телефонов:

* **iPhone** кладёт видео отдельным файлом: `IMG_0007.HEIC` + `IMG_0007.MOV`
  (в выгрузке iCloud — `IMG_0007_HEVC.MOV`). Пара склеивается по имени, HEIC
  конвертируется в JPEG, видео идёт как есть.
* **Android** (Pixel, Samsung и другие) прячет видео **внутрь JPEG**: файл один, а
  в его хвосте дописан MP4. Программа находит границу, разрезает файл на кадр и
  видео и отправляет тем же живым снимком. Если это не Motion Photo или разобрать
  не вышло — уходит обычным фото, ничего не теряется.

Режимы (`LIVE_PHOTO_VIDEOS`):

* `live` — парой, одним сообщением (по умолчанию);
* `send` — кадр и видео двумя отдельными сообщениями;
* `skip` — видео не отправлять, только кадр.

Что важно знать:

* Отправка идёт **через бота**. Если бот не настроен или его Bot API server старый
  (метода `sendLivePhoto` там нет), пара автоматически уходит двумя сообщениями —
  ничего не теряется, просто это уже не Live Photo. Через аккаунт (MTProto) пара
  не собирается: она всегда мелкая и всегда проходит через бота.
* В архивном режиме (`SEND_AS_DOCUMENT=true`) Live Photo не собирается: там смысл
  в несжатых оригиналах, поэтому оба файла уходят как документы.
* Видео Live Photo записывается в базу вместе с кадром — если тот же `.MOV`
  попадётся отдельно в другой папке, он не уйдёт второй раз.
* Ограничения: кадр до 10 МБ, видео до 50 МБ. Если пара не влезает, она уходит
  двумя сообщениями.

## Подпись под сообщением

`CAPTION_STYLE=pretty` (по умолчанию) — дата крупно, техническое мелким шрифтом,
путь и хеш спрятаны в раскрывающуюся цитату:

```
📷 12 марта 2020, 23:16
iPhone 11 Pro · 3.2 МБ · Live Photo
#2020 #март2020 #live #IMG_0373
▸ 2020/IMG_0373.jpg
  sha:fb1e7549ae08bcc3
```

Модель камеры берётся из EXIF, хештеги делают архив искомым: `#2020` — весь год,
`#март2020` — месяц, `#IMG_0373` — конкретный кадр. Если достоверной даты съёмки
нет, перед ней ставится `≈`.

Другие варианты: `plain` — простой текст без разметки (как было раньше),
`minimal` — только дата и хештеги.

## Дубликаты

Три независимых уровня — ни один файл не уйдёт дважды:

1. **По содержимому.** sha256 каждого файла хранится в базе. Один и тот же снимок
   под разными именами и в разных папках отправится один раз.
2. **По имени в пределах одного запуска.** `IMG_0001.HEIC` и `IMG_0001.JPG` в одном
   каталоге — это один кадр в двух форматах: отправляется один, выбор задаёт
   `PAIR_PREFER` (`auto`: JPEG для ленты, оригинал для документов). `.MOV` рядом с
   фото того же имени — это Live Photo: по умолчанию он не отбрасывается, а уходит
   вместе с кадром одним сообщением (см. раздел выше).
3. **По имени между запусками.** Если тот же кадр в другом формате уже был отправлен
   раньше, он опознаётся по имени без расширения **и** совпадающей дате съёмки
   (`CROSS_RUN_NAME_CHECK`). Одного имени мало: `IMG_0001` встречается на каждом
   iPhone, поэтому дата обязательна.

**Уже отправленные дубли.** Если архив собирался старой версией, видео Live Photo
могли уйти отдельными сообщениями. `npm run start -- cleanup` покажет такие
(команда `/cleanup` у бота — то же самое), а `cleanup --yes` удалит эти сообщения
и пометит файлы в базе, чтобы они не отправились снова. Бот должен быть админом
с правом «Удаление сообщений».

**Повторное подключение того же диска.** Ничего не отправится второй раз: решает
sha256 из базы, а не путь. Чтобы при этом не перечитывать терабайты, хеши кэшируются
не только по пути, но и по «имя + размер + время файла» (`FAST_REMOUNT_MATCH=true`) —
поэтому диск, смонтированный как `/Volumes/USB-1` вместо `/Volumes/USB`, обрабатывается
почти мгновенно.

## База отправленного

SQLite (`data/cloudtelega.db`), через встроенный `node:sqlite`; при желании можно
заставить использовать конкретный драйвер: `CLOUDTELEGA_SQLITE=node|better`.

* `files` — `sha256` (UNIQUE, ключ дедупликации), имя, путь, размер, дата съёмки и её
  источник, имя без расширения, статус (`pending` / `sent` / `failed` / `skipped`),
  способ отправки, топик, `message_id`, ошибка, а также **`file_id`**,
  `file_unique_id`, `file_type` и `video_file_id` (видео Live Photo).
* `hash_cache` — кэш sha256 по `(путь, размер, mtime)`, чтобы повторный запуск не
  перечитывал весь диск заново.
* `topics` — соответствие «год → message_thread_id» для режима топиков.
* `meta` — служебное.

Первые 16 символов хеша есть в подписи каждого сообщения — по ним файл находится
поиском внутри Telegram.

```bash
sqlite3 data/cloudtelega.db "select name, size, status, message_id, file_id from files limit 20;"
```

### Поиск и ссылки на сообщения

В мастере на панели «База отправленного» есть поиск по имени файла и папке
(регистр не важен, кириллица тоже) и фильтр по состоянию: всё / в архиве /
ошибки / пропущенные. Каждая найденная запись — ссылка прямо на сообщение
в Telegram.

То же самое из терминала и от бота:

```bash
npm run start -- find IMG_0373      # покажет дату, размер, статус и ссылку
```

```
/find IMG_0373       у бота в личке
```

Ссылки не хранятся в базе, а собираются на лету из `chat_id`, `topic_id` и
`message_id`, которые записываются при каждой отправке с самой первой версии.
Поэтому ссылки появляются сразу у всего, что уже отправлено, — **переотправлять
архив не нужно**. Формат: `t.me/c/<чат>/<сообщение>`, а в группе с темами —
`t.me/c/<чат>/<тема>/<сообщение>`, чтобы сообщение открывалось внутри своего года.

### Зачем нужен `file_id`

Это идентификатор уже загруженного файла на серверах Telegram. По нему бот может
отправить файл **мгновенно и без повторной загрузки** — на этом работают `/get` и
`/random`. Полезно знать:

* `file_id` действителен только для того бота, который загрузил файл; для другого
  бота он бесполезен (а вот `file_unique_id` одинаков у всех и годится как ключ
  сравнения);
* у файлов, ушедших через аккаунт (больше 50 МБ), `file_id` нет — бот их не
  загружал. Такие бот присылает через `copyMessage` из хранилища, результат тот же;
* у Live Photo хранятся оба идентификатора: кадра (`file_id`) и видео
  (`video_file_id`), поэтому `/get` пересобирает Live Photo целиком;
* `/status` показывает, у скольких файлов есть `file_id`.

## Лимиты и надёжность

* Bot API: 50 МБ на файл. Если поднять свой
  [Bot API server](https://github.com/tdlib/telegram-bot-api) с `--local` и указать
  `TELEGRAM_BOT_API_ROOT`, лимит станет 2000 МБ.
* MTProto (аккаунт): 2 ГБ, с Premium 4 ГБ — Premium определяется автоматически
  при обновлении профиля из Telegram.
* Фото с превью: до 10 МБ, всё что больше — автоматически документом.
* Live Photo: кадр до 10 МБ, видео до 50 МБ, отправка только через бота.
* Flood-лимиты: между отправками пауза `SEND_DELAY_MS` (по умолчанию 1200 мс),
  ответ `429 retry_after` от Bot API обрабатывается автоматически, FLOOD_WAIT в
  MTProto — тоже. При заливке большого архива не ставьте паузу в 0.
* Сеть отвалилась — файл помечается `failed`, запуск продолжается; `retry` вернёт
  его в очередь. Причина сохраняется в базе целиком, а не как «fetch failed».

## Когда что-то не работает

Первое место, куда смотреть, — лог на шаге «Проверка и запуск». Туда попадает
всё, что программа пишет в терминал: повторы запросов, ответы Telegram, неудачные
конвертации, причины пропуска файлов. Строки помечены временем и цветом,
переключатель «Только проблемы» оставляет предупреждения и ошибки, кнопка
«Скопировать лог» отдаёт текст целиком.

Ошибки не сокращаются до `fetch failed`. Node прячет настоящую причину сетевого
сбоя внутри `err.cause`, поэтому программа её разворачивает и переводит:

```
Bot API getMe: сервер отказался от соединения (ECONNREFUSED).
  Попытка 1 из 4 заняла 13 мс, повтор через 2000 мс.
  Адрес: http://127.0.0.1:8098/bot***/getMe
```

Токен в лог не попадает — вместо него `bot***`.

Что обычно означают сообщения:

| Что в логе | Что случилось |
|---|---|
| `не удалось определить адрес сервера (ENOTFOUND)` | нет интернета или DNS не отвечает; при блокировке Telegram нужен VPN |
| `не удалось подключиться за отведённое время` | чаще всего блокировка провайдером — проверьте, открывается ли api.telegram.org |
| `сервер отказался от соединения (ECONNREFUSED)` | не запущен свой Bot API server из `TELEGRAM_BOT_API_ROOT` |
| `вместо ответа Telegram пришла веб-страница` | трафик перехватывает прокси или блокировщик |
| `сертификат подписан сам собой` | HTTPS проверяет антивирус или корпоративный прокси |
| `Unauthorized (HTTP 401)` | токен бота неверный или отозван |
| `bot was kicked (HTTP 403)` | бота выгнали из группы |
| `chat not found (HTTP 400)` | выбрана не та группа или бота в ней нет |
| `not enough rights (HTTP 400)` | бот не администратор или ему запрещено публиковать |
| `flood limit, просит подождать N с` | слишком частые запросы; программа ждёт и продолжает сама |
| `AUTH_KEY_UNREGISTERED` | сеанс аккаунта отозван, нужен повторный вход на шаге 3 |

«Посмотреть, что нашлось» тоже пишет по шагам: сколько папок обходит, сколько
медиафайлов нашлось в каждой, сколько из них уйдёт, разбивку по годам и —
поимённо — что схлопнулось в пары и почему.

### Файлы, которые не удалось прочитать

Отдельная строка в итогах и красная плитка над логом: **сколько файлов диск
не отдал**. Это важно, потому что такие снимки в архив не попали — считать
резервную копию полной и стирать что-то с диска нельзя.

Ошибок обычно много сразу, поэтому они сведены по кодам, а не по строке
на файл: «213 × диск не смог прочитать файл (ошибка ввода-вывода) (EIO)»
и пять примеров путей.

| Код | Что это | Что делать |
|---|---|---|
| `EIO` | накопитель не смог прочитать файл | битые сектора, отходящий кабель или плохой USB-порт. Переподключите в другой порт без хаба; если ошибок много — копируйте с диска всё, что читается, на другой носитель, пока он жив |
| `ENODEV`, `ENXIO`, `ESTALE` | устройство отвалилось посреди обхода | проверьте кабель и смонтируйте заново |
| `EACCES`, `EPERM` | нет прав на чтение | дайте доступ своему пользователю |
| `EROFS` | файловая система стала «только для чтения» | так ядро защищается от сбойного диска — проверьте накопитель |
| `ENOSPC` | кончилось место | освободите место под временные файлы (`TMP_DIR`) |

`EIO` — не ошибка программы: так отвечает сам накопитель. Появление таких
ошибок на внешнем диске стоит воспринимать как предупреждение о его скорой
смерти.

`CLOUDTELEGA_DEBUG=1` добавляет к ошибкам стек вызовов.

## Если что-то не ставится

**`npm error command failed … better-sqlite3` / `gyp ERR! not found: make`** — старая
версия проекта тянула нативный модуль. Обновитесь и переустановите зависимости:

```bash
git pull
rm -rf node_modules package-lock.json
npm install
```

Native-зависимостей в проекте больше нет, компилятор не нужен.

**`ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite`** — Node старее 22.5. Обновите Node
(`nvm install 24 && nvm use 24`) либо поставьте `npm i better-sqlite3`.

**`input buffer is not a HEIC image`** — файл с расширением `.heic`, но не HEIC внутри.
Оригинал в этом случае всё равно отправляется, терять ничего не нужно.
